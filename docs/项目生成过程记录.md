## 四、构建方案设计（为什么这样做）

### 4.1 组装方式：Python 拼接脚本而非手工编辑

模板 `template.html` 有 1400+ 行（CSS + WebGL shader + 演讲者模式 + 同步 JS），手工编辑极易出错。沿用记忆中验证过的方案：

```
build.py 读 SKILL 模板 → 六步拼接 → 写出 ppt/index.html
  1. 正则替换 :root 主题色 6 行 → 森林墨
  2. 替换 <title>（消灭 [必填] 占位符）
  3. 在 </style> 前插入追加 CSS（导航簇 + 学习卡片助手类）
  4. 在 </body> 前插入 data-goto 解析器 <script>
  5. 替换 <!-- SLIDES_HERE --> 为全部 30 页
  6. 正则替换 SPEAKER_NOTES 数组（含 window.__SPEAKER_NOTES__ 赋值，不重复）
```

**核心优势：页码自动重算。** 每页 chrome 里的 `NN / TOTAL` 用占位符 `@NN@ / @TOTAL@`，组装完成后按最终顺序统一替换——以后往里加模块内容页，重跑 `python build.py` 即可，所有页码自动对齐，不用手改 30 处。

### 4.2 自定义导航实现（用户的核心诉求）

- **封面 = 首页**（hero dark），带"进入目录"按钮
- **左上角常驻按钮簇** `#nav-back`：`⌂ 首页` + `☰ 目录`，任何页面一键回去；演讲者模式/观众屏自动隐藏（`body.ppt-audience` 时 display:none）
- **目录页**（hero light）：5 个 Part 分栏列出 20 个模块，每条都是 `<button data-goto="m01-parts-of-speech">`
- **跳转解析器**（追加在 </body> 前）：点击时反查 `data-slide-id` → 索引 → `go(i, {force:true})`。**不硬编码页码**，所以以后增删页面目录跳转依然准确
- **每个模块幕封**带"↖ 返回目录 · Contents"
- 模板原有的底部圆点、← → 翻页、滚轮、ESC 总览、P 演讲者模式全部保留

### 4.3 追加的 CSS 助手类（技能明确允许：缺类就补在模板 <style> 里）

| 类 | 用途 |
|---|---|
| `#nav-back` | 左上角首页/目录按钮簇 |
| `.learn-card` | 一个语法点卡片：衬线标题(中+英) + 顶部细线 |
| `.ex-line` / `.ex-gl` | 英文例句行（目标结构斜体加重 `.tgt`）+ 下方中文小注 |
| `.mist` (+`.m-label`/`.m-body`) | "常见错误 · Common Mistake" 提示框 |
| `.practice` (+`.p-label`/`.p-q`/`.qnum`) | "练一练 · Quick Practice" 区块 |
| `.sv-main` / `.sv-cols` | 内容页双列网格容器 |

双语排版约定：中文规则/标签用 `--sans-zh` & `--serif-zh`；英文例句用 `--serif-en`；目标语法用 `em`/`.tgt` 斜体强调；元数据用 `--mono`。

### 4.4 主题节奏（技能硬规则）

## 五、踩坑与修复实录（本次真实发生）

### 坑 1：Python f-string 漏写生成器子句
`contents()` 里 `"".join(f'...{m[0]}...' f'...{m[1]}...')` —— 相邻 f-string 被 Python 拼成**一个**字符串，根本不是生成器表达式，`m` 未定义 → `NameError`。
**修复**：改为显式 `for mm in ms:` 循环拼接。

### 坑 2：PILOT 字典键与 data-slide-id 不一致
`PILOT["m1pos-a"] = slide("m1-pos-overview", ...)`，组装时用 `PILOT[pid]` 的键（`m1pos-a`）当 order 里的 sid，而备注里写的是真实 id（`m1-pos-overview`）→ NOTES 排序时 `IndexError`。
**修复**：PILOT 字典键统一改为真实 slide-id。

### 坑 3：批量重命名的 sed 漏掉列表末项
`'"%s","' % old` 这种带尾逗号的匹配，替换不到列表最后一个元素（后面是 `]` 不是 `,`）→ `KeyError: 'm1pos-d'`。
**修复**：直接 Edit 精确改 `pilot_for()` 的两个列表。

### 坑 4：校验器要求每条备注都有 transition
第一版备注只有一条带 transition → 29 个 ERROR（同时 28 个 talk 条数不足的 WARNING）。
**修复**：`N()` 帮助函数把 transition 设为必传参数，逐条写了有意义的转场语；talk 全部补到 3 条。

### （规避）坑 5：撇号炸校验器 —— 靠设计直接绕开
记忆里的坑：SPEAKER_NOTES 单引号字符串含 `'` 会炸括号扫描器。英语语法 deck 满篇 `Don't / It's`。
**规避**：所有备注字符串**一律用双引号**（Python `json.dumps` 输出天然双引号），从设计上根除。

### （规避）坑 6：Chrome 截图写不进 projects 目录
**规避**：截图统一写 `E:\ClaudeCode\temp`，用 `file:///E:/...` URL + `?mode=preview&slide=N` 定位到指定页。

### 排查出的隐藏大 Bug：`slide()` 参数顺序错位

放大字号后逐页截图目检，发现所有正文页的 chrome（页眉）折行、页码掉到底部、内容疑似溢出。用 PIL 放大截图角落逐像素排查，再 dump 生成的 HTML 对比，定位到根因：

**PILOT 调用写的是 `slide(id, theme, foot_left, "M01", <大段正文>)`——第 4 个位置参数落到了 `body` 形参上，整页正文被塞进了页眉 chrome 的第二个 `<div>` 里，frame 里只剩 "M01" 一个词。** 之前校验器只查备注/结构不查视觉，所以一直没暴露。

**修复**：把 `slide()` 签名改为 `slide(mid, theme, foot_left, code="GRAMMAR", body="")`，与全部 8 个调用点的实参顺序一致，一行改动根除。

### 大字导致的溢出与收敛

修复 chrome bug 后重新截图，仍有 3 页底部溢出（frame 是 `overflow:hidden`，会硬裁掉最后一行）：

- JS：在 NAV_JS 的点击委托里**最先**判断 `.aha`（必须在 `data-goto` 分支之前 `return`，否则点按钮会同时触发翻页）：`closest('.mini-p')/.p-q/.practice` 上 toggle `.revealed`，并把按钮文字换成「▲ 收起答案」。
- **标记模式**：每个知识点卡片尾部加一行 `.mini-p`（「练」标签 + 题目 + Aha! 按钮 + 隐藏答案），模块末练习页用 `.p-q`（大题号行）。题目形如 `There are five ___ on the desk.（boxs / boxes）`，答案形如 `✔ boxes — box 以 x 结尾，复数加 -es：box → boxes。`

### 3. Learn with Adam 动态 IP 字样
- `.ip-brand` 绝对定位于目录页右上角（top 8.2vh / right 6vw，与 chrome 错开）。
- 动效纯 CSS：`background-clip:text` 渐变流动（`lwa-shine` 4s 无限循环，墨绿↔灰绿扫光）+ 一颗脉冲圆点（`lwa-pulse` 2s）。「动态字样」不引任何外部库。

### 4. 目录页重排（修溢出）
- 每个模块压成**单行**：mono 编号 + 中文名 + 斜体英文名（超长省略），行高 `.4vh`。
- Part 重新分栏：左列 PART I+II，右列 PART III+IV+V；去掉 lead 行；标题降为 5vw。
- 目检确认：20 个模块 5 个 Part 全部在屏内，含新加的 IP 字样。

### 5. 页面拆分与主题节奏
- M1 实词页（名词+动词+形容词+副词四卡）答案展开后超高 → 拆成两页：`m1-pos-content-words`（名词/动词，dark）+ `m1-pos-content-words-b`（形容词/副词，light）。

### 6. 本轮踩坑
- **坑 7：`.mini-p` 问题太长会把 Aha! 按钮挤到第二行，展开的答案就被推出 `.frame` 底部裁掉**（虚词页连词卡）。修法：缩短题干（`I like math ___ I don't like history.` → `He was tired, ___ he kept going.`）+ 删右列冗余注释行（`时间/地点`、`连接并列句或从句`），答案压成单行。教训：**写 mini-p 时要按「答案展开后」的高度预算页面**，按钮换行会多占一行。

## 五·叁 显示不全全面修复实录（第 7 轮用户反馈：「部分页面的显示不全」+ 两张截图：M09 两页大标题横向被裁）

### 1. 问题定位
用户截图显示 M09 两页的 `h-xl` 大标题（如「与过去事实相反：had done + would have done」）因 `white-space:nowrap` 超出画布宽度被硬裁。排查发现是系统性问题，不止这两页：
- `head()` 助手给所有标题加了 `white-space:nowrap`，但字号固定 6.2vw，长标题必然溢出；
- 侧带问题：按「答案全部展开」的最坏状态衡量，部分页面底部也超高。

### 2. 修复手段（三层）
1. **长标题改写**：3 个最长标题（M09 两页 + M19 动词老坑页）把公式从中文大标题挪到英文副标题行——中文主标题保持最大字号，后排可读性不受损；
2. **`head()` 自动缩字号安全网**：新增 `_est_em()` 估算标题渲染宽度（CJK≈1em、拉丁≈0.56em），`font-size = min(6.2vw, 88vw×0.96/估宽)`，从根上杜绝横向裁切（本轮共 8 页自动缩 0.03–0.55vw，肉眼几乎无感）；
3. **纵向收紧**：全局微调 `.learn-card`（gap 1→.7vh、padding-top 1.2→.9vh）、`.sv-main` 行距、`.practice` 块与 `.ans` 内边距、18 个练习页的口诀 `margin-top:2.2vh→1vh`；三页结构重排（M1 总览删冗余 lead、M3 总览两列改 `sv-main` 三列网格、目录页标题 5vw→4.5vw + 单元格 padding 减半）；练习页标题统一 `xl_style="font-size:4.6vw"`（练习页标题次要，题干字号不动）。

### 3. 验证方法升级：DOM 溢出探针（替代肉眼逐页截图）
写了 `_make_probe2.py / _make_probe3.py`（项目根目录保留，回归测试可复用）：把 deck 复制一份、注入探针脚本（等 `document.fonts.ready` 后遍历每个 `.slide` 的全部元素，报 `scrollWidth/scrollHeight > clientWidth/clientHeight` 的即是被 `overflow:hidden` 硬裁的元素），用无头 Chrome `--dump-dom --window-size=1440,810` 读回报告。两个副本：probe2 = 默认态，probe3 = 全部 Aha! 答案预展开态（最坏高度）。

- 修复前：横向裁切若干页、展开态 22 页底部超高（练习页普遍 +106px）；
- 修复后：**两态均报告 NONE**（全 99 页、无横向无纵向裁切）。

### 4. 本轮踩坑
- **坑 10：`head()` 的 `nowrap` + 固定字号是定时炸弹**——标题短时看不出，一旦内容页写长标题（带公式）必裁。修法是「估宽自动缩字号 + 长内容挪副标题」双保险。
- **坑 11：探针第一版噪音大**——用默认 800×600 窗口跑，4:3 视口把所有元素都报成纵向溢出；且没等 webfont 加载，字宽度量不准。修正：`--window-size=1440,810`（16:9 实际比例）+ `document.fonts.ready` 后再量 + 只报 frame 边界的纵向裁切（元素级 line-height 噪音过滤掉）。
- **坑 12：`.sv-cols` 上加 `grid-template-columns:repeat(3,1fr)` 不会重排两个 `.col` 子容器**——列变窄但卡片不重新分布（M3 总览页）。要真重排就得把卡片打散成单层网格（改用 `.sv-main`）。
- **坑 13：截图偶发静默失败**——同一命令重跑一次即出图；遇到 PNG 缺失先重试再排查。

发布过程并不顺利，网络环境是主因，记录如下：

- **网络**：github.com:443 直连不通（需 VPN 且不稳定），但 **api.github.com 可达** →
  `git push` 走不通时，改走 **Git Data API**（blobs → trees 自底向上 → commit → PATCH refs）。
  为此写了 `tools/_api_push.py`：把本地提交逐对象重建到远端，并断言每个 SHA 与本地一致，
  因此远端 main 与本地提交逐字节相同，日后 VPN 通了直接 `git push` 即可快进。
- **认证**：GCM 的 OAuth 令牌时而读不出（`git credential fill` 偶发挂起/超时）→
  改为**用户自建 Personal Access Token**（仅 repo 权限），本人独立终端执行
  `git credential approve` 存入系统凭据管理器——令牌不进对话、不落明文文件。
- **API 侧踩坑**：
  - **坑 17**：`git cat-file -p <tree>` 对非 ASCII 文件名会加引号转义（`"\351..."`），
    引号被当成文件名传给 API 导致 tree SHA 不匹配 → 改用 `git ls-tree -z` 取原始字节名。
  - **坑 18**：固定列切片解析 tree 行（`line[13:53]` 等）差一列 → ls-tree -z 后按
    空格/制表符 split，不再依赖列号。
  - **坑 19**：GitHub API 的 commit date 只收 ISO 8601，而 `git cat-file` 给的是
    Unix 时间戳（`1790082284 +0800`）→ `datetime.fromtimestamp(ts, tz).isoformat()` 转换。
- **安全约束（工具侧）**：自动化分级器两次拦截「令牌物化」——禁止把令牌（哪怕前 4 位/长度）
  打印进对话、禁止写入任何文件。最终形态：单条命令内 `git credential fill` 管道导出
  `GH_TOKEN` 环境变量，用完即弃。
- **隐私**：`ppt/images/`（用户报 bug 的本地截图）写入 .gitignore，不入公开仓库。
